# go-compliance v0.1.0

First tagged release of the core module (`github.com/larsartmann/go-compliance`)
and the hub workspace. Released 2026-11-19 (tag `77881b3`); this release page
was created retroactively on 2026-11-24 — the tag originally shipped with no
notes, and v0.2.0 (2026-11-20) supersedes it as `latest`.

## Core module

- Compliance state model: `compliant` / `failing` / `stale` / `never-covered`,
  branded types (`RepoName`, `SourceName`), sentinel errors classified through
  go-error-family.
- Frozen v1 wire contract: marshal/decode byte-exact against a real BuildFlow
  `compliance --json` fixture (golden tests); `schema_version >= 2` rejected
  like the overview decoder.
- Source-agnostic evidence fold with `worstStepLimit` capping.
- `Source` adapter interface: `FileSource` (piped v1 document with missing-file
  TTL backoff) and `CommandSource` (spawns `buildflow compliance --json`).
- Reporter SDK one-liner: `compliance.Record` with memory and file writers.

## Hub module (binary via flake, not go-get-able)

- cmdguard CLI (`serve`, `report`, `table`) with BuildFlow-parity flags.
- go-output fleet table (severity cells, state labels, worst-first sort).
- SQLite evidence cache (go-sqlitestore) with versioned migrations.
- Discovery daemon client over a unix socket with never-covered derivation.
- SSE events hub with Last-Event-ID replay, ring-buffer store, heartbeats.
- Realtime dashboard (templ-components + go-datastar patches, three-way row
  diffing, embedded SDK bundle), content negotiation, `?state=` filtering.
- go-health probe surface (`/healthz` `/readyz` `/startupz` `/version`),
  sd_notify readiness via go-daemon, hardened systemd unit under `deploy/`.
- Live re-derive (M27): debounced refresher keeps served rows live; E2E
  contract test pins store-write → browser patch.
- Bind posture: localhost-only default, `unix:` socket mode, non-localhost
  warning. Benchmarks: fold @341 ≈ 150µs, derive zero-alloc.
